## 2. C 型两机下界复核（已独立验证）

`2436.091、2301.057、2107.812、1877.191、1561.554、1494.169`（总和 11777.874 s）。

该值只是固定任务组合下的最优，不是原问题全局下界，也不能证明 23 架次不可行。

## 3. 方法：含时限的联合重构（本轮新增）

原两次失败尝试（`joint_recon.py`、`pool_opt.py`）的共同缺陷是 **选择 MILP 不含时限**，
选出的低能耗/低工时组合在完整排程时出现数千秒硬时限违反。

本轮新增 `q2_transfer.py`：

1. 每个候选架次预计算**最晚开始时间 LS**（同时满足硬时限与零延误）与完成期限 `D=LS+duration`；
2. 以"逐机型任务时长最优划分"为代理（B/C 用 2 机精确子集和，A 用总时长/4），快速筛选单箱迁移候选；
3. 只对代理改善的候选做**完整时限感知排程**（`feas_sched.best_feasible_order`，B/C 全排列、A 局部搜索，硬时限/零延误作为可行性门禁）；
4. 排程失败只丢弃候选，不记为不可行。

主线的关键 move：把 23 架次方案（5969.038 s）中 C 型关键任务的少量货箱迁移到 A/B 或其它 C 任务，
使 C 型 6 任务总时长从 12035.375 s 降到 11784.354 s，最优二划分从 6064.952 s 降到 **5903.038 s**。

## 5. 负结果（如实记录）

- **22 架次 ≤6300 s**：从 22 架次最优（6361.574 s）做单箱迁移，代理值可降到 6104.073 s，
  但完整排程始终不满足硬时限/资源约束；从 23 架次新方案做多架次联合重构（释放 3–6 个相关架次、
  现场生成候选、含时限 MILP 修复）也未产出 22 架次可行解。**不能据此判定 22 架次不可行。**
- **23 架次在 ≤5903.038 s 下降能耗**：
  - 单箱迁移：全部候选的能耗改进都同时使代理完成时间 >5903.038 s（candidates=0）；
  - C 型 36 箱重组 MILP（固定 17 个 A/B 架次，含有效时限约束）：求出能耗 67.9213 kWh 的组合，
    但完成时间 5969.038 s > 5903.038 s，按约束被拒。
  说明"少 1 架次"与"低能耗"在当前解附近存在真实冲突。

- 5903.038 s 是**固定 24 架次任务组合**下的 C 型两机排程最优值，不是原问题全局下界。
- 23 架次新方案是**启发式已知最好可行解**；没有全局最优性证明。
