## 4. 能否通过运输时序/组批取消 RS04（本轮判定：当前资源结构下不可行）

几何事实（PixelIsPoint 逐点验证）：
- **T22(S015) 只能由西点位覆盖**：RS01/RS04(西) OK；RS03(北) "视线未认证"；RS02(东) "距离上界未获认证"。
- **T16(S008) 只能由西点位或北点位覆盖**：RS01(西) OK、RS03(北) OK；RS02(东) 距离不足。
- RS01(西) 在役窗口仅 **[723.951, 4695]**；RS03(北) 窗口在 6303 s 之后，无法回补 T16/T22 的中段。

因此取消 RS04 需要 **T16 与 T22 同时落入 RS01 的 4695 s 窗口**，即二者开始时刻均 ≤2831.3 s。
用带 LS（硬时限+零延误）的 B 型精确排程 MILP 验证：

| 约束 | 结果 |
|---|---|
| T16≤2831.3 且 T22≤2831.3 | **无解**（status=0 Infeasible） |
| T16,T22≤2600 / 2200 / 1900 | 均无解 |
| 不加上限（仅 LS） | 可行，B 型完成 5986.3 s |

尝试放宽 T22（单独 ≤3104.4，允许 T16 后移）时，T16 落到 3900 s，其通信缺口 772.353 s——
RS01 已结束、RS02 几何不可用、RS03 尚未开始。
若改为延长 RS01 覆盖两者，则 RS01 返航推迟 → 共用 R01 的 RS03 随之推迟 → 破坏 RS03 对 S004/S005/S011 的覆盖。
**故在当前 2 中继机 / 6 能源组件与发布运输结构下，RS04 不能安全取消；** 要取消必须联合重排运输时刻与中继资源
（本轮已把冲突定位到"T16/T22 争用 RS01 窗口"这一具体结构）。

## I. 连续认证进展（收紧证书）

原保守证书对运动/静止混用同一粗距离上界与走廊半径，产生大量假阴性。改进：
1. **距离上界收紧**：线段两端点到固定端点的三维距离取 max（距离函数沿直线段凸，最大值必在端点），去掉"每度位移上界"粗项；
