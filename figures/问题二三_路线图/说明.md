# 问题二、问题三路线图说明

## 用途与底图口径

本目录只做**呈现**：路线数据直接读自已发布结果，不改动任何数值。底图与
`figures/地形与服务区分布/raw_dem_terrain_plan.*` **完全一致**（脚本直接 `import 绘制三维地形`
复用同一套 `Scene` / `terrain_rgba` / 标注工具，因此底图不会与地形图跑偏）：

- 30 m DEM 柔和山体阴影 + 每 100 m 主等高线（50 m 辅助线）；
- O01 为水平原点，+x 向东、+y 向北，坐标为相对 O01 的公里数；
- 服务区白点带“编号 + 地面高程”标注，O01 为橙色星标，右上角指北针，右侧为高程色标。

读图约定：每条折线是**一个架次**的水平航迹 `O01 → 访问服务区（按顺序）→ O01`，
去程与回程在同一线段上重合。机型用**颜色 + 线型**双重编码（灰度打印也能分辨）：
**A 型深红实线、B 型深蓝虚线、C 型近黑点线**。

底图是浅色绿/黄/棕地形，所以路线改用低明度、地形中不存在的色相
（`#C62828` / `#0D47A1` / `#212121`，不透明度 0.95、线宽 1.55），
并在**去重后的每个航段**下铺一层浅色衬底（白、宽 3.05、不透明度 0.55），
使路线在深色山影和浅色高地上都能看清；衬底按航段去重，因此不会因多架次重复而叠成白带。
问题三的三个中继悬停点改用统一的俯视四旋翼图标，并用紫、蓝、橙三色及邻近文字区分点位；
回传虚线先铺深色衬底再画彩色。五张图底部的灰色说明已移入本文档，图例置于地图左上空白区。

四张问题二路线图的差别主要在**单点专用架次的数量**（实测）：

| 口径 | 架次 | 其中单点往返 | 合并两个服务区 | 平均每架次服务区数 |
|---|---|---|---|---|
| 时间优先(主方案) | 24 | 22 | 2 | 1.08 |
| 均衡 | 20 | 18 | 2 | 1.10 |
| 能耗优先 | 18 | 15 | 3 | 1.17 |
| 架次优先 | 18 | 15 | 3 | 1.17 |

即：架次越少，越靠“拼线”（一条架次串两个服务区）把服务区并进同一架次，单点专用往返随之减少；
时间优先把 15 个服务区几乎全部拆成单点往返，因此架次最多、完成时间最短、能耗最高。

## 复核证据

- 架次数与 `方案对比_四个口径.csv` 一致（24/20/18/18），问题三为 22 架次 + 4 条中继架次；
- 脚本对每条路线做结构化自检：路线 artist 条数 = 架次数，且每条折线的端点坐标与
  `访问服务区顺序` 解析出的节点坐标逐点一致，颜色=机型（实测 24/20/18/18/22 条、端点不符 0 条）；
- 中继层自检：回传链路条数 = 悬停点数（3 条），并断言悬停海拔 = 该点地面高程 + 300 m；
- 版面自检（`visual_qa.audit_layout`）：五张图均 PASS，节点标签越界 0、重叠 0；
- 对比度复核（对成图像素算 WCAG 对比度，底图为同一底图的无路线版本）：
  A/B/C 路线相对背景的对比度中位数 3.9 / 5.2 / 8.9，5% 分位 3.2 / 4.4 / 2.7；
  改版前（半透明 0.72 + 亮色）只有 1.9 / 1.1 / 1.4——其中橙线仅有 1.06，
  在浅绿地形上几乎看不见，这也是本轮加深颜色的原因；
- 灰度预览在 `_qa/`（三种机型另有实线/虚线/点线区分，灰度下仍可分）。

## 复现

从 `UAV` 目录运行：

```powershell
python 绘制路线图.py
```

脚本只读 `results/` 下的 CSV 与 `绘制三维地形.py` 的底图函数，不写回任何结果表。
