# 问题二改进求解（可复现）

本目录是问题二改进实验的**可复现代码**。原求解入口 `问题二_求解.py` 固定「每架次 ≤3 站」，
本实验放开到 ≤4 站并做多起点并行搜索；**单变量消融显示 4 站容量未生效（3 站与 4 站同预算结果相同），改善来自长时/多起点搜索**；结果写入独立目录
`results/问题二_改进方案/`，验证通过前不覆盖原主方案与提交工作簿。

## 2. 方法

- `q2_solver4.py`：`问题二_求解.py` 的副本，唯一的两处**语义**改动：
  `if len(areas) > 3:` → `> 4:`，`if len(spec["stops"]) < 3 and …` → `< 4`（即放开到 4 站）。
- `parallel4.py` / `parallel4b.py`：多起点并行 ALNS（joblib，14 进程），同时跟踪
  时间优先 / 能耗优先 / 架次优先三种准则；初值来自已有非支配解。
- `feas_sched.py`：**带硬时限与零延误约束**的逐机型调度优化（B/C 全排列、A 局部搜索）。
- `apply_feas.py`：把 `feas_sched.py` 的顺序真正应用到 4 个发布方案并重新导出（makespan/能耗不变，B 型时序更优）。
- `joint_recon.py` / `pool_opt.py`：候选池 + 集合划分 MILP 的联合重构尝试（见第 6 节，未获得可行改进）。
- `q2_verify.py`：独立验证，不复用求解器中间量。

## 5. 瓶颈分析（为什么 5903.038 s 难以突破）

固定当前组批/路线/机型时：A 型 11 架次总时长 19505.490 s（/4=4876.372）、B 型 7 架次 11546.133 s
（/2=5773.067）、C 型 6 架次 11777.874 s（/2=5888.937）。对 C 型 6 个时长（2436.091、2301.057、
2107.812、1877.191、1561.554、1494.169）做全部 2^6 二划分，最优最大子集和恰为 **5903.038155 s**
（不存在两个子集都 < 5903.038 的划分）。因此**仅重排现有架次不可能突破 5903.038 s，必须改变
C 型的组批或机型分配**。该值只是固定任务组合下的最优，不是原问题全局下界。

## 6. 尝试过但未成功的路线（保留真实实验结果）

- **联合重构 MILP**（`joint_recon.py`）：固定 A/B，把 C 的 36 箱重新组批并允许换机型，直接
  最小化各机型工作量上界 Z。候选 565 条，得到 Z=5773.067 的选择（该 Z 的下界由固定 A/B 部分决定：B 型 11546.133/2=5773.067，不代表可实现改善），但全精度解码出现 hard=4831.8 s 违约——
  MILP 未含时限，说明低 Z 解不一定可按时执行。
- **候选池 + 联合调度 MILP + 惰性 no-good 割**（`pool_opt.py`）：池 1564 条候选（`runs/` 已随仓库，可复现该规模），MILP 每轮
  15 s，10 轮内 Z 降到 5542.046，但带时限调度始终未通过，未产出可行改进；该路线未跑完，
  不能据此下结论。
- **完成时间上限搜索**（`parallel_cap.py`）：从较差初值出发，未能在 T≤6600/7200 找到可行解；
  上限实验结论由已有 404 个候选解析给出（第 4 节）。

## 7. 独立验证与局限

`q2_verify.py` 对 4 个方案逐架次独立复算：箱覆盖唯一、质量/体积、逐段剩余载荷、能耗、
飞行时间、逐箱交付时刻、硬时限/延误、无人机与电池区间不重叠、SOC 余量——**4/4 PASS**。

局限：
1. 4 站是**搜索截断**，不是题面约束；未证明 >4 站无更优解。单变量消融（`ablation_3v4.py`）显示 3 站与 4 站同预算最优指标相同、4 站容量未生效，因此本次改善不能归因于放开站数。
2. 全部结果为启发式搜索的已知最优，**没有全局最优性证明**；`joint_recon`/`pool_opt` 的
   MILP 只对固定候选池成立。
3. 作业高度基准（P-01）与 DEM 像元语义（P-02）仍是待决口径，记录于 `results/建模算法审计/12_独立核验原始输出.json` 的 `元信息.口径`；主方案最低 SOC
   20.137% 较紧，统一口径后需优先复核。
4. 未使用 CP-SAT（本机未安装 ortools），时限调度用启发式列表+局部搜索，不是精确调度。
